任務看板 ·「卡住的工作」現況 vs A+ 案

已簽核但沒人回報完成的任務：搬到下面另開一區（現況），還是留在原欄、用 pill 標出量級（A+）。

2026-07-29 · 數字為 prod 實測（台灣福祉）· 依 docs/modules/design-research-taskboard.md（2026-07-27 已裁定 V3 Signal）

問題是上線第一天才看得出來的。 功能剛上線，所有歷史已簽核任務的 work_status 都是預設的 open、 而且都超過 7 天 —— 「卡住」的判定對它們全部成立，一條規則把整欄搬空。

01競品研究早就寫了，而我違反了它

§0 定位：我們不是泛用 PM Kanban，是告警 triage 佇列（Datadog／PagerDuty 模型）—— 卡片是系統產生的、主要動作是分流＋確認、有時效壓力與信心度這兩個 PM 工具沒有的維度。
§2 共同弱點 #3：membership ≠ 嚴重度 —— 東西「在逾時欄」但沒說逾時多久，少了 triage 需要的量級。 Datadog 有 duration，多數 PM 板沒有。
我做的正是被點名的那件事：把「卡住」做成欄位歸屬（另開一區＝membership）， 而研究說 membership 本身不夠、要的是量級。

告警佇列不會因為某個告警「卡住」就把它移到另一張表 —— 它是在同一個佇列裡標出嚴重度與 duration。
競品做法對這題的意義
Datadog／PagerDuty 嚴重度是一等公民 ＋ 佇列顯 time-in-status 與 responder 「卡住 N 天」該是卡片上的量級，不是另一個容器
Linear 極致克制 · 預設少顯，要看什麼用 display options 自己開 想「只看卡住的」→ 篩選，不是獨立區塊
Asana 兩層：卡面快速視圖 ＋ 點開深入 細節進 drawer，卡面只留 triage 要的
Jira 卡片最多 3 個欄位、色條區分 別在卡上疊太多
Trello／Monday 彩色狀態一眼分流 ⚠️ 顏色狂歡 = 要避開的反例
而且解法早就裁定了、只是還沒做。 design-research-taskboard.md §4 有一行 ⬜ 待做：
「逾時欄顯『逾時 N 天』 —— 依據 Datadog duration；membership ≠ 嚴重度；現只分欄，未顯量級」

2026-07-27 裁定的 V3 Signal 卡片裡就有「逾時 N 天」實心 pill。 「卡住 N 天」是同一個模式的延伸，不是新發明。

03A+ 的四個設計決定，各自的依據

決定怎麼做依據
卡住＝pill 不是區塊 「卡住 9 天 · 待指派」實心 pill，跟「逾時 N 天」同款 Datadog duration · membership ≠ 嚴重度（§2 弱點 #3）
色 ＋ 形 ＋ 字 卡住用 ● 圓點、逾時無形；紅／琥珀分兩級 修「只靠顏色編碼」（§2 弱點 #1）· 色盲友善
只在異常時顯 沒卡住的卡片不長 pill，維持乾淨 Linear 克制 · 同「信心度只在中／低顯」既有做法
要只看卡住的 → 篩選 頂部 display options 切「全部／只看卡住的」 Linear display options（§1）· 不用另開容器
順手補掉一個欠很久的 ⬜。 §4 那行「逾時欄顯『逾時 N 天』」從 2026-07-24 就列為待做，一直沒補 —— 而這次踩的坑正是同一個病（把量級做成歸屬）。這次一起做完。

04為什麼不選 B（只算功能上線後簽核的）

B 是「加一個日期門檻，歷史資料不進來」—— 主看板也不會空，但致命傷是它會讓那 13 張 真實存在的任務從追蹤裡消失，而那些正是最該被看到的：已經簽核、放著、沒有人回報。

另外它要在程式碼裡記一個「功能上線日期」，半年後沒有人記得那個判斷式為什麼存在。

05A+ 的代價（誠實列出）

  • 已簽核欄會變長 —— 13 張加上原本的。目前限 30 張，超過標「顯示最近 30 筆」。
  • 卡片多一個 pill —— 跟 Jira「最多 3 個欄位」的建議還有餘裕，但要盯著不再往上加。
  • 「只看卡住的」要多做一個篩選 —— 但那是 Linear 驗證過的模式，比另開區塊更省版面。
現況的代價是第一眼看到兩個空框，那個沒辦法之後補； A+ 的代價（欄變長、多一個 pill）都是可控且可調的。
