06要注意的兩個坑

N-2 · P0只擋側欄不擋 API

盤點結果：135 個端點只有 9 個沒守衛，而且都是刻意的 （打卡／改自己密碼／查自己權限，全走 @CurrentUser）。 目前沒有已知漏洞。

但機制是 fail-open —— if (!roles) return true， 忘記寫的懲罰是「安靜放行」。而 M1 要一次補 15 項，正是最容易漏的時候。

真正危險的形狀：@Query("tenantId") ＋ 內部開 aiproot_admin 上下文。 漏了 @Roles 就能傳別家 tenantId 跨租戶讀資料。
本次新增的 /completion-signals/* 正是這個形狀（有加，但只差一行）。
✅ M0.9：守衛改 fail-closed（9 個端點加 @AllowAnyUser() 明示意圖） ＋ 跨租戶形狀測試。
❌ 不做 metadata 快照測試 —— 容易變成「壞了就更新快照」的橡皮圖章， 比沒有更糟，因為它給人安全感。
N-3 · P1改名之後找不到原本的頁

「定時任務 → 自動化」「素材看板 → 素材」「今日日誌 → 對話紀錄」—— 既有使用者會找不到。

自動化 原「定時任務」
改名的項目在側欄掛一次性提示，看過就消失。比寄信或公告便宜得多。
