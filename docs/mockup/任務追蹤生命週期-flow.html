⚠️ 實測誤判率 33%：「好了嗎」含「好了」。 prod 有 6 則被關鍵字抓到的「完成語意」，其中 2 則其實是在催問—— 「有幾個半成品的Bom建好了嗎」「請問改好了嗎?」。
方向最糟：把「還沒做完」關成「做完了」。

解法：先擋疑問句，再看完成詞。 出現 嗎 / 呢 / ? / ？ 一律不判完成。
「快好了」不是「好了」。語意判斷錯成「進度」是安全的，錯成「完成」不是—— 後者會讓系統宣稱一件沒做完的事做完了（doc F-15，P0）。
所以只認高把握的完成語意（已完成／好了／換好了／已處理／已設定／OK）， 其餘一律當進度。寧可少接一筆，不可誤報一筆。
⭐ 而且那 2 則誤判，不需要語意判斷就能擋掉。
兩則都是指派者引用自己的指派訊息去催進度—— 「洪鈺仙 引用 洪鈺仙」「郁芬Sandra 引用 郁芬Sandra」。

結構規則：回覆者 == 原訊息發話者 → 這是催問，不動任何狀態。
零誤差、不依賴語言，而且結構與疑問句兩個獨立過濾器各自都抓到同樣 2 則——雙保險。
一則訊息 @ 多人時不整張關掉。「@小陳 @小李 這兩台都要保養」—— 小陳回「好了」只結掉他那一份；拆不開時降級成進度，並在看板標「部分回報」（F-16）。

05系統回覆 · 為什麼一定要回一句

二廠設備群
林班長@陳○○ 三號機軸承明天記得換一下
換好了
✓ 已記錄完成　更換三號機軸承
陳○○ · 開了 3 天 · 若記錄有誤請回「更正」

三個理由

  • 回饋閉環：沒有回應的話，人不知道系統有沒有接到，下次就不會再回了。
  • 可撤回：判錯了，當場回「更正」就能還原——比事後去網頁改容易得多。
  • 擴散示範：其他人在群裡看到這個互動，就學會了怎麼用。不需要教育訓練。
但要節制。只在「成功接住」時回，接不到任務時不要回—— 在群裡說「我找不到對應的任務」只會製造噪音，而且暴露系統的失敗。 接不到的統一進後台的「未接住」清單（§08）。

07⭐ 未完成怎麼一直看得到（不靠強制）

v2 原本把輸入搬到 LINE，卻把可見性留在網頁——而他們沒帳號。 結果是當責人根本看不到自己還開著幾件。這一段補這個洞。

但不是「每天強制更新進度」。一個人手上 5 件未完成，強制每天更新 ＝ 每天 5 次義務， 第三天開始複製貼上，第五天沒人理。

四個好處

  • 零新義務——那則回報他本來就會發
  • 時機對——落在他正在回報的當下，不是隨機打斷
  • 免費——用 reply token 回覆，不是 push（push 才計費）
  • 不公開點名——是回他自己的訊息，不是對全群喊
⭐ 沒發回報的人就不會收到。
這比催他更好——「沒發回報」本身就是主管該看到的訊號， 那屬於主管的看板（§09 逾期未完成），不是往同仁身上加的負擔。
三條節制規則（否則這顆會長成催辦，也就是釘釘那條路）：
· 只回他自己發的那則，沒發不回
· 只用 reply token 不用 push——技術上就擋掉主動打擾
· 未完成 0 件時不回（連「今天沒有未完成」都不要回）
不要把普通聊天誤判成回報。只認明確的回報樣式 （「今日工作內容回報」「今日進度回報」「日期＋姓名＋晨會」）。
拿不準就不回 —— 少回一次沒事，亂回一次很吵。（doc F-21）

08⭐ 持續追蹤是紀律，不是不作為

不確定的任務一直留著、直到有人確認——這是對的。 但前提是標籤要說對話。

標籤在說什麼對不對
未完成工作沒做完 人做完了但沒回報時 → 是假的
未確認完成沒有人確認過 永遠是真的
只要標籤是後者，持續留著就完全正確——系統誠實地表達「我不知道」， 直到有人告訴它。那是紀律。
（同 ITIL 的 resolved vs closed：停在 resolved 等使用者確認，沒有人認為那是系統失職。）

改標籤直接解掉「信任」的疑慮

❌「你還開著 3 件未完成」
→ 他心想：我明明做完了，這系統是壞的
✅「以下 3 件尚未確認完成」
→ 他心想：喔，我去確認一下
同一個狀態、同一份資料，第二種說法沒有人被冤枉。
信任問題不是持續追蹤造成的，是措辭造成的。

結束的四個選項

對應四種不同的後續：完成進統計、不用做了排除在分母外、 轉給別人要有人接、做不到是求救訊號要主管看到。

「做不到」是四個裡最有價值的一個。 它是唯一會讓事情往上走的選項，其他三個都是往下收。 沒有它，卡住的人只能不按任何鍵，任務靜靜躺著沒人知道。

15明確不做的

AI 不自動標完成

AI 只能寫 status，永遠不得寫 work_status。 GitHub 花七年才把 closed 拆成 completed／not planned，起因就是 stale bot 大量自動關閉。

沒引用的「好了」不算

群裡單獨說「好了」不會關掉任何任務——無法確定在講哪一件。只在看板提示，由人確認。

不做自動催辦

沒有逾期自動私訊、沒有自動標記主管。釘釘做到 IM 市佔第一，仍因員工側缺乏關閉權而反噬到創辦人卸任。

不做完成關卡

不要求拍照或填表才能結案。完成條件的技術依賴愈多，關不掉的任務就愈多。

未完成不自動進日報

一件做兩週的事會出現在 14 份日報裡，把「今天真正做了什麼」埋掉。

不做逾期判定

due_at 目前全是 null。用「開了幾天」代替，不宣稱逾期。

對推廣的建議：把順序反過來

風險先綁定才有價值

綁定是一次性摩擦，但它擋在所有價值前面。

prod 已經給了答案：可用了數月，4 / 44。
其餘 90% 的人拿不到任何東西，客戶看到的是「系統沒在動」。

這是典型的 B2B 導入牆：入場費收在價值之前。
採用先給價值，綁定拿更多

Day 1　系統直接在群裡運作（不用綁、不用登入）
　　主管看得到看板、完成訊號接得住 → 當天就看到東西在動

之後　「想看自己的工作紀錄、想收個人日報？綁一下」
　　綁定變成「拿更多」，不是「入場費」

跟整個產品主張同一件事：不要求員工先改習慣。綁定本身就是一次習慣改變。
但要誠實記下代價。未綁定時當責人只能用 display_name（文字）表示， 那不是身分——同名、改暱稱、一人多帳號都會對錯。
緩解：看板對未綁者標「（未綁定）」不宣稱精確；同群內 display_name 重複時不自動歸屬； 綁定後回填即自動修正。（doc F-23）
