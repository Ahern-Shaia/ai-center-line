導入 Checklist · 日誌與日報全員上線

目標：讓公司所有人開始使用「群組日誌」與「個人日報」。先小範圍測試，通了再全員推。
對象：客戶窗口 / 總經理室 ｜ 標示：窗口 資訊窗口　總經理 管理層　員工 全體
一句話：功能都準備好了。這次要做的不是設定系統，是讓大家把 LINE 綁上 —— 綁定＝橋樑，沒綁的人發言歸不到他、也沒有個人日報。

階段 A先小範圍測試明天

  • 窗口挑 2–3 位業務當試點（其他人先別動）
  • 試點員工用自己的 LINE 加公司 Bot 好友 → Bot 傳「開始綁定」→ 點一下完成（約 1 分鐘）
  • 試點員工私訊 Bot 幾則今天的工作內容（例：「今天跑了 A 客戶、B 客戶報價」）
  • 試點員工打開個人日報 → 看 AI 有沒有整理出來 → 一鍵送出給主管
  • 總經理/主管確認有收到「○○ 已送出日報」的 LINE 通知、並在戰情室「部門日報」看得到
  • 窗口這條龍走通 → 進階段 B；卡住哪一步 → 回報我們（附截圖）

階段 B全員導入下週

  • 窗口把 Bot 的 ID 或 QR code 發到各部門群（pin 公告最省事）
  • 全體員工照階段 A 的方式各自綁定（加好友 → 點綁定）
  • 窗口過幾天回報我們綁定人數，我們一起看還有誰沒綁

同步權限設定（總經理看全公司、主管看自己部門）

  • 總經理建部門（設定 → 部門/成員 → 部門分頁 → 新增部門）
  • 總經理建部門主管：成員分頁 → 新增成員 → 角色選「部門主管」+ 選「所屬部門」
  • 總經理把 LINE 群組分派到部門（設定 → 通訊管道 → LINE 群組，每群選部門）
  • 總經理員工綁定後系統會自動歸部門；推不出來的，在成員頁自己調整所屬部門（新功能）
最容易忘：部門主管的「所屬部門」一定要選，不選＝他幾乎看不到東西。完整步驟見《權限設定手冊》。

準備窗口 / 總經理要準備的

  • 窗口公司 Bot 的 ID / QR code（發給員工加好友用）—— 不確定就問我們
  • 總經理（選配）一份「員工 → 部門」名單，用來核對系統自動歸的部門對不對
員工端不需要提供帳號密碼、不用填任何資料 —— 只要用自己的 LINE 加好友、點綁定。

這次不用Ragic 整合可以先放著

日誌與日報是「LINE → AI → 報告」，完全不需要先整合 Ragic。Ragic 是之後的加分項（讓分析更準），不是這次上線的前提。之後要接時，總經理可在「資料來源」頁自己設定。

設錯時對照這裡

部門主管登入後什麼都看不到？

最常見是忘了選「所屬部門」。回成員分頁編輯他，把所屬部門補上。

部門主管看得到別部門的資料？

檢查他的角色是不是被設成「總經理室」了 —— 那個身分本來就看全公司。改成「部門主管」。

一位主管同時管兩個部門？

目前一個人只能綁一個部門。要同時看兩個，只能給「總經理室」（但會看到全公司），或請 AIPROOT 評估。

主管看得到部門，但裡面沒有任何任務／日報？

兩個可能：① 步驟 3 沒做，LINE 群組還沒分派到這個部門；② 員工還沒在 LINE 上送出日報。

現在好像每個人都看得到全部？

因為多數帳號目前是「總經理室」。把該當主管的人逐一改成「部門主管」並指定部門即可。

一頁總結

目標：總經理看全部、部門主管看自己部門 總經理 → 角色設「總經理室」（要請 AIPROOT 建） 部門主管 → 角色設「部門主管」＋ 指定「所屬部門」 三步驟（都在「設定」選單裡）： 1. 部門/成員 → 部門分頁 → 建好所有部門 2. 部門/成員 → 成員分頁 → 建主管（部門主管 + 所屬部門） 3. 通訊管道 → LINE 群組 → 每個群選它屬於哪個部門 最容易忘：主管的「所屬部門」一定要選，不選＝他看不到東西。
總經理（總經理室帳號）由 AIPROOT 建立；部門主管（部門主管）總經理自己就能建。

用「群組 ID 小幫手」快速取得 LINE 群組 ID

LINE App 裡看不到群組 ID。這支專用小幫手 bot 幫你拿到它：把它加進群，它就把群組 ID 回給你。 加進去 → 抄下來 → 貼到要用的地方 → 拿到就可以把它移除。
給誰看：AIPROOT 內部同仁（A 節一次性設定）／客戶窗口（B 節取 ID）· v1.0（2026-07-31）

先搞懂：這支 bot 只做一件事

它只回「這個群的 ID」。不看對話、不分析、不記錄任何訊息 —— 跟每天幫你整理日誌的那支分析 bot 是兩支不同的 bot。

為什麼要另外一支？因為分析 bot 每家公司一支、設定較重；這支「群組 ID 小幫手」是全體共用的通用工具， 純粹幫你把群組 ID 讀出來，用完即可移除。因為它不碰任何對話資料，也就沒有把資料混到別家公司的風險。

A一次性設定（AIPROOT · 只做一次，之後所有客戶共用）

建立一支「群組 ID 小幫手」bot 並登錄到系統。做過一次就跳到 B 節。
1在 LINE Developers 建一個新的 Messaging API channel

名稱取「群組 ID 小幫手」之類好認的。這支是 AIPROOT 平台自己的，不屬於任何一家客戶。

2Webhook 設成跟分析 bot 同一個網址

Messaging API 分頁 → Webhook URL 填 https://<你們的網域>/line/webhook（與分析 bot 相同）， 打開「Use webhook」。系統靠 bot 身分自動分流，不必另開端點。

3打開「允許加入群組」

Messaging API 分頁 → Allow bot to join group chats 設為 Enabled。 沒開的話它根本進不了群，也就無從回 ID。

4記下三樣，登錄到系統

從 channel 取得 Bot user ID（Uxxxx…）、Channel secret、Channel access token（長期）， 跑下面這段 SQL 登錄成 utility bot（tenant 留空）：

-- 用與 server 相同的 LINE_CONFIG_ENC_KEY 加密，否則之後解不開
INSERT INTO line_bot
  (tenant_id, name, bot_user_id, kind,
   channel_secret_enc, channel_access_token_enc, status)
VALUES
  (NULL, '群組 ID 小幫手', '<Bot user ID · Uxxxx>', 'utility',
   pgp_sym_encrypt('<channel secret>',        '<LINE_CONFIG_ENC_KEY>'),
   pgp_sym_encrypt('<channel access token>',  '<LINE_CONFIG_ENC_KEY>'),
   'active');
enc key 一定要跟 server 那把一模一樣 加密用的 LINE_CONFIG_ENC_KEY 若跟 server 環境變數不同，webhook 解密會失敗、bot 不會反應， 而且不會有明顯錯誤 —— 會像「設定都對卻沒反應」。
5冒煙測試

把這支 bot 加進一個測試群 → 應該立刻收到一則含群組 ID 的歡迎訊息。收到就代表設定成功。

B取得群組 ID（誰都能做 · 可重複）

下面五步，一分鐘拿到一個群的 ID。
1把「群組 ID 小幫手」加進目標 LINE 群

用這支 bot 的 QR code 或 ID 邀請它進群（跟平常拉人進群一樣）。

2它會立刻回一則訊息，裡面就是群組 ID
群組 ID 小幫手
你好，我是 aiproot 的群組 ID 小幫手。 本群組 ID： Cxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx （複製上面這串，貼到 aiproot 後台的「LINE 群組」欄位即可） 需要再看一次，在群裡打「群組ID」我就再回你。取得後可將我移除。

沒看到？在群裡打「群組ID」三個字，它會再回一次。

3長按那串 ID 複製

C 開頭那一長串就是。長按 → 複製。

4貼到要用的地方

貼到通知設定的「LINE 目標群」，或直接回報給 AIPROOT。這串 ID 貼哪、給誰用，就對到哪個群。

5拿到就好，可以把小幫手移出群組

它的任務就是回 ID，拿到後移除即可；留著也不會做任何事（不看對話、不記錄）。

連打兩次「群組ID」只回一次？正常。同一個群 30 秒內重複只回一次，避免洗版。等一下再打即可。

0先搞懂：一條規則在做什麼

花一分鐘看懂這個，後面每一步都會知道自己在幹嘛

一條規則就是一句話：

「當 Ragic 的某張表單有人改資料時，把其中幾個欄位的內容，發到某個 LINE 群。」

所以設定時你只要回答三個問題：

問題你要決定的
什麼時候要通知？哪一張 Ragic 表單 · 新增資料時？改資料時？還是刪除時？
通知內容要有什麼？那張表單裡的哪幾個欄位（例：客戶名稱、機台編號、狀態）
要通知誰？哪一個 LINE 群，或哪一位同仁的私訊
為什麼還要回到 Ragic 貼一段網址？ 因為 Ragic 不會主動告訴任何人「我這裡有人改資料了」。 我們要在 Ragic 裡留一個通報用的網址，Ragic 才知道要把消息送到哪。 這件事只要做一次，之後就一直有效。

建立時間–
右邊那個數字是訊息裡的排列順序，依你點選的先後決定。 想調順序就把它取消再重點一次。

步驟 4 · 通知對象

6先選「管道」——要發到群組還是私訊

卡片最上面是「管道」，兩個開關，預設是「LINE 群組」（會亮起紫色）。 點哪一個，下面出現的欄位就不一樣。

畫面上會看到
管道
LINE 群組
LINE 私訊

選「LINE 私訊」的話，下面會變成挑一位同仁——而且那個人必須已經綁定 LINE， 沒綁的不會出現在清單裡。

7填「LINE 目標群」

這一格會依你的帳號權限長成兩種樣子其中一種。看到哪一種就照哪一種做， 兩種都能完成設定。

情況 A · 你看到一個輸入框（多數帳號是這種）
LINE 目標群
貼上 LINE 群組 ID（Cxxxx...）
看不到群組清單有兩個可能：這個帳號沒有檢視 LINE 群組的權限， 或該 bot 還沒在任何群裡收過訊息（群組是收到訊息才會登錄）。

怎麼做：去下面那段拿到群組 ID，貼進去即可。

情況 B · 你看到一個下拉選單
LINE 目標群
台灣福祉 · 技術工程群▾
清單裡找不到？改成手動輸入群組 ID

怎麼做：直接選。格式是「公司名 · 群組名」，一個人管好幾家時靠前面那段分辨。 要的群不在清單裡就點下面那行切成手動輸入。

群組 ID 去哪裡拿？ LINE App 裡看不到群組 ID——它不是給使用者看的東西。 唯一的取得處是我們自己的 通訊管道 頁： 找到那個群，點一下群名下面那行灰色小字，就會複製完整的 ID。
為什麼有些帳號看得到清單、有些看不到？ 清單只列出機器人已經收過訊息的群（群組要收到訊息才會被登錄）， 而且需要「檢視 LINE 群組」的權限。兩者缺一就會變成情況 A。 這不影響設定結果——手動貼 ID 跟從清單選，存進去是一樣的東西。
8按「儲存規則」

存好之後畫面會給你一段網址，下一節要用。

3回到 Ragic 貼上網址

整個流程最常出錯就在這一步，慢一點做
1複製剛才那段網址

存檔後畫面上就有。之後也可以在規則列表按「複製網址」重新拿，不用刪掉重建。

2在 Ragic 打開同一張表單

就是剛才填路徑的那一張。貼到別張表單是常見錯誤，而且不會有任何錯誤訊息。

3點上方的「工具」，在展開的選單裡找 Webhook

「工具」在表單上方那排（新增 / 工具 / 重新整理）。點下去會展開一整片選單， 分成六個區塊。Webhook 在右下角那一區「同步與通知」裡面。

找不到的人多半是在找一個不存在的子選單——這是「明明設定了卻沒通知」的頭號原因。
4把網址貼上去，儲存
5登出 Ragic，再重新登入
這步不能跳過 Ragic 會把設定暫存起來，不重新登入的話剛貼的網址不會真的生效。 我們踩過這個坑：設定完全正確，就是沒通知，登出重進之後立刻就通了。

4測試看看通不通

不要用「等真的有人改資料」來驗證，自己動手測一次
1在 Ragic 那張表隨便改一筆資料，按儲存

改一個不影響業務的欄位就好，例如備註加一個字。

2看那個 LINE 群有沒有收到

正常是幾秒內就到。超過半分鐘沒來，直接看下一節。

連續測兩次卻只收到一則？ 這是正常的。30 秒內同一筆資料重複觸發只會發一次，避免有人連按儲存就洗版。 等 30 秒再測即可。

5沒收到通知？照這個順序查

不要憑猜的，先看「通知紀錄」——它會直接告訴你事情卡在哪一段

第一站永遠是：通知設定 → 通知紀錄 分頁。看到什麼，就往下對照。

完全沒有任何紀錄
代表 Ragic 那邊根本沒把消息送出來，事情還沒到我們這裡。
回第 3 節，依序確認：
① 網址有貼進那一張表單嗎（不是別張）
② 有找對地方嗎——Webhook 在「工具」展開後右下角「同步與通知」那一區
③ 貼完有登出 Ragic 再登入嗎
有紀錄，寫著「未訂閱此異動」
消息有進來，但這條規則沒勾這種異動類型。
按規則的「編輯」，把「更新資料」（或你需要的那種）勾起來。
有紀錄，寫著「重複略過」
30 秒內同一筆資料重複觸發，只送第一次。
正常行為，不用處理。等 30 秒再測。
有紀錄，寫著「推送失敗」
我們收到了，但 LINE 那邊拒絕了。
看那一列的「說明」欄。最常見的是機器人已經被移出那個群組，把它重新加回去即可。
有紀錄，寫著「已送出」，但群組還是沒訊息
我們這端完成了推送。
檢查機器人是不是還在那個群裡；也確認你看的是不是同一個群。
收到了，但內容都是「（未填）」
通知有發，但欄位抓不到值。
點開那一列會展開診斷說明，它會直接告訴你是哪一種：
① 那些欄位在 Ragic 本來就是空的 → 正常
② 勾的欄位跟這張表單對不上 → 表單改過了，重新「抓取欄位」再存一次
「抓取欄位」失敗時，畫面會直接告訴你哪裡錯 訊息會明確指出是帳號名、表單路徑、表單索引還是金鑰的問題， 照它說的那一格去改就好。不要看到失敗就先去換金鑰 —— 多數情況不是金鑰的問題。
紀錄裡「規則」那欄寫著「—（舊版記錄 · 未留規則）」 那是舊版系統留下來的資料，當時沒有記錄是哪條規則觸發的。不是規則被刪掉，不用去找。

6之後要修改規則

直接改就好，不要刪掉重建
規則列表上有「編輯」按鈕 要換欄位、改通知對象、加勾一種異動類型，都用編輯。 改完網址不變，不用回 Ragic 重貼。
不要用「刪掉重建」來修改 重建會產生一段新的網址，舊的立刻失效。 你會得到一條看起來正常、實際上收不到任何消息的規則——除非你記得回 Ragic 把新網址再貼一次。
你想做的怎麼做
換掉幾個顯示欄位編輯 → 步驟三重新勾選 → 儲存
改成通知另一個群編輯 → 步驟四換下拉 → 儲存
暫時不要收通知規則列表把它停用（不要刪，之後還要用）
換成另一張 Ragic 表單這個要新增一條規則——網址是綁表單的，換表單等於換一條線
