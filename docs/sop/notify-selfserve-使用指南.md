# 通知設定使用指南 SOP

> aiproot 員工在戰情室前端自助設定通知規則：**什麼事發生（來源）→ 通知誰（管道）**。免找欄位編號、免寫程式。
> 版本：v2.0（2026-07-25 · 改多來源）｜對應：notification-hub（notify v3）｜適用：具 `notify-config:manage` 權限的 aiproot 員工

---

## 0. 觀念：一條規則 = 來源 → 欄位 → 對象

| 元素 | 選項 |
|---|---|
| **來源**（什麼事發生） | ① **Ragic 表單異動**（新增/更新/刪除）② **系統內部事件**（如外勤打卡異常）|
| **欄位**（訊息顯示什麼） | 由來源自動列出可用欄位 → 勾選 + 排序 |
| **管道對象**（通知誰） | LINE 群組 / LINE 私訊（指定成員）|

> 兩種來源在畫面上操作方式**完全一樣**：選來源 → 系統列欄位 → 勾選 → 選對象。

## 1. 前置

- [ ] 帳號有「**通知設定**」權限（AIPROOT 管理 → 權限管理；aiproot_admin / consultant 預設有）。
- [ ] 該公司已註冊 LINE Bot（否則沒有可選的群組、也推不出訊息）。
- [ ] **只有 Ragic 來源才需要**：該公司 Ragic **API 金鑰**（需帳號管理者權限，用來自動讀表單欄位）。

---

## 2. 建立規則

戰情室 → **AIPROOT 管理 → 通知設定** → 右上「**＋ 新增通知規則**」。

### 步驟 1 · 選觸發來源
點「Ragic 表單異動」或「系統內部事件」。

### 步驟 2A · Ragic 表單（若選此來源）
1. 選 Ragic 帳號（沒有就「＋ 新增帳號」：伺服器 / 帳號名 apname / 顯示名 / API 金鑰 → 儲存；金鑰**加密存、不回明碼**）。
2. 貼表單路徑（如 `/service-tickets/10`）→ 按「**抓取欄位**」→ 顯示「✓ 已讀取〔表單名〕· N 個欄位」。
3. 勾選要通知的異動：新增 / 更新 / 刪除。

### 步驟 2B · 系統內部事件（若選此來源）
1. 從下拉選事件（例：**外勤打卡異常**）。
2. （選填）設數值門檻，例：「推算時速 ≥ 150」才通知 —— 可避免雜訊。

### 步驟 3 · 勾要通知的欄位
點欄位勾選；右側數字＝訊息中的排列順序（依勾選先後）。可填「自訂訊息標題」。

### 步驟 4 · 通知對象
- **LINE 群組**：從該租戶已登錄群組選。
- **LINE 私訊**：選成員（**需該成員已綁定 LINE**）。

按「**儲存規則**」。

### 步驟 5 · 只有 Ragic 來源需要：接上 Webhook
儲存後會產生一個 **Webhook 網址** → 複製 → 到 Ragic 該表單 → **工具 → Webhook** → 貼上 → 儲存。
> **系統內部事件不需要這步**，存檔即生效。

---

## 3. 驗證

- **Ragic 來源**：改一筆該表單資料並儲存 → 目標對象收到通知。
- **內部事件**：觸發該情境（例：外勤打卡異常）→ 目標對象收到通知。

---

## 常見問題

| 症狀 | 原因 / 解法 |
|---|---|
| 「抓取欄位」失敗 | Ragic 金鑰非帳號管理者 / 表單路徑錯 / 伺服器（server）選錯 |
| Ragic 改資料但沒通知 | Webhook 網址沒貼進該表單 / 該異動類型沒勾 / 規則被停用 |
| 內部事件沒通知 | 門檻設太高被過濾 / 規則停用 / 目標成員未綁定 LINE |
| 通知顯示「（未填）」 | 該欄位本來就空；或 Ragic 完整資料讀取失敗（會降級用 webhook 帶的值）|
| 私訊沒收到 | 該成員未綁定 LINE（規則會記錄「通知對象尚未綁定 LINE」）|
| 要改規則 | 目前無「編輯」：**停用/刪除後重建**（Ragic 來源的 webhook URL 會變、需重貼）|
| 看不到「通知設定」選單 | 帳號缺 `notify-config` 權限 → 找 aiproot_admin 分配 |
