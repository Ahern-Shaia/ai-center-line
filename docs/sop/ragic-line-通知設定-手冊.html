Ragic 改一筆資料 → LINE 群組自動收到通知

這份手冊帶你從零設定一條通知規則。不需要寫程式，全部在畫面上點選完成。 照著做大約 10 分鐘。
適用對象：AIPROOT 內部同仁（需具「通知設定」權限）· 最後更新 2026-07-29
這份手冊的順序
  1. 先搞懂：一條規則在做什麼
  2. 開始前要準備的三樣東西
  3. 在系統裡建立規則（四個步驟）
  4. 回到 Ragic 貼上網址 ← 最常出錯的一步
  5. 測試看看通不通
  6. 沒收到通知？照這個順序查
  7. 之後要修改規則

0先搞懂：一條規則在做什麼

花一分鐘看懂這個，後面每一步都會知道自己在幹嘛

一條規則就是一句話：

「當 Ragic 的某張表單有人改資料時，把其中幾個欄位的內容，發到某個 LINE 群。」

所以設定時你只要回答三個問題：

問題你要決定的
什麼時候要通知？哪一張 Ragic 表單 · 新增資料時？改資料時？還是刪除時？
通知內容要有什麼？那張表單裡的哪幾個欄位（例：客戶名稱、機台編號、狀態）
要通知誰？哪一個 LINE 群，或哪一位同仁的私訊
為什麼還要回到 Ragic 貼一段網址？ 因為 Ragic 不會主動告訴任何人「我這裡有人改資料了」。 我們要在 Ragic 裡留一個通報用的網址，Ragic 才知道要把消息送到哪。 這件事只要做一次，之後就一直有效。

1開始前要準備的三樣東西

缺一樣就會卡住，先確認齊全再開始
1你的帳號要有「通知設定」權限

登入戰情室後，左側選單看得到 通知設定 就代表有。 看不到就找 AIPROOT 管理員開通。

2那家公司要先接好 LINE 機器人

沒有機器人就沒有可以選的群組，訊息也發不出去。 這通常在導入時就做好了，不確定就先問一下。

3那家公司的 Ragic「API 金鑰」

系統要用它去讀那張表單有哪些欄位，你才不用自己去背欄位編號。

去哪拿：Ragic 右上角 → 個人設定 → 基本資料 分頁 → 捲到最下面找到 API Key 那一列 → 點「產生新的 API Key」。

「個人設定 → 基本資料」最下方會看到
兩步驟驗證切換開關
API Key產生新的 API Key
LINE 通知設定切換開關
務必用「帳號管理者」帳號去產生 讀取表單欄位這件事 Ragic 只開放給帳號管理者。用一般使用者的金鑰會失敗， 而且錯誤訊息不會告訴你是權限問題——你會以為是路徑打錯，然後在那裡卡很久。
只有「Ragic 表單」這種來源需要第 3 樣。 如果你要設的是系統內部事件（例：外勤打卡異常），跳過金鑰，也不用做第 3 節。

2在系統裡建立規則

左側選單 → 通知設定 → 右上角「＋ 新增通知規則」

步驟 1 · 選擇觸發來源

以下四個標題就是畫面上卡片的標題，照著對就不會迷路。

1選「Ragic 表單異動」

另一個選項「系統內部事件」是我們系統自己偵測到的狀況，這份手冊先講 Ragic。

畫面上會看到
● Ragic 表單異動　○ 系統內部事件

步驟 2 · 選擇 Ragic 帳號與表單

2選 Ragic 帳號

下拉裡已經有那家公司就直接選，然後跳到步驟 3。第一次設定某家公司才需要按「＋ 新增帳號」。

一個網址就能填完新增帳號的三格 在 Ragic 隨便打開那家公司的任何一張表單，看網址列，它天生就分成三段：
Ragic 的網址一定長這樣
https://ap16.ragic.com/taiwanhomecare/service-tickets/10
網址的哪一段填進哪一格說明
ap16 伺服器 從下拉選同名的那個。不要用猜的——每家公司在哪台機器是 Ragic 決定的， 選錯的話「抓取欄位」會失敗，而錯誤訊息看起來像路徑錯。
taiwanhomecare 帳號名 網域後面、下一個斜線前面那一段。這是 Ragic 給那家公司的代號， 不是中文公司名，原字照抄（含大小寫）。
/service-tickets/10 （步驟 3 的表單路徑） 剩下的那一整段，含開頭的斜線。這格不在新增帳號裡填， 是下一步「抓取欄位」時才用。
2b另外兩格

顯示名：只給我們自己看的名字，取你認得出來的即可（例：「台灣福祉」）。 這格不影響任何功能，打錯了隨時可以改。

API 金鑰：把前一節產生的那串貼上。

存好之後金鑰不會再顯示出來 這是刻意的（加密保存），不是沒存到。所以產生金鑰時就先貼到記事本備份， 不然要重新產生一次——而重新產生會讓舊的立刻失效。
3貼上表單路徑，按「抓取欄位」

就是上面網址拆解裡黃色那一段 ——在 Ragic 打開你要通知的那張表單，複製網址第二個斜線之後的全部。

要填的是這一段（含開頭的斜線）
/service-tickets/10
網址如果還有 ? 之後的東西，那些不要複製進來。
按下「抓取欄位」後，成功會看到
✓ 已讀取「維修保養單」· 23 個欄位
「抓取欄位」失敗的三個原因，依可能性排序 ① 金鑰不是帳號管理者的　② 表單路徑打錯（少了斜線、多了問號後面那段）　③ 伺服器選錯（ap16 / www 那格）

（仍在步驟 2 的卡片裡）勾選要通知的異動

4勾選要通知的異動類型
新增資料
更新資料
刪除資料

多數情況只要「新增」和「更新」。刪除通常不用通知，除非那張表刪掉代表某件重要的事。

步驟 3 · 選擇要通知的欄位

5點選要出現在通知裡的欄位

右上角有「全選」，欄位很多時先全選再取消不要的，比一個一個點快。

畫面上會看到

步驟 4 · 通知對象

6先選「管道」——要發到群組還是私訊

卡片最上面是「管道」，兩個開關，預設是「LINE 群組」（會亮起紫色）。 點哪一個，下面出現的欄位就不一樣。

畫面上會看到
管道
LINE 群組
LINE 私訊

選「LINE 私訊」的話，下面會變成挑一位同仁——而且那個人必須已經綁定 LINE， 沒綁的不會出現在清單裡。

7填「LINE 目標群」

這一格會依你的帳號權限長成兩種樣子其中一種。看到哪一種就照哪一種做， 兩種都能完成設定。

情況 A · 你看到一個輸入框（多數帳號是這種）
LINE 目標群
貼上 LINE 群組 ID（Cxxxx...）
看不到群組清單有兩個可能：這個帳號沒有檢視 LINE 群組的權限， 或該 bot 還沒在任何群裡收過訊息（群組是收到訊息才會登錄）。

怎麼做：去下面那段拿到群組 ID，貼進去即可。

情況 B · 你看到一個下拉選單
LINE 目標群
台灣福祉 · 技術工程群▾
清單裡找不到？改成手動輸入群組 ID

怎麼做：直接選。格式是「公司名 · 群組名」，一個人管好幾家時靠前面那段分辨。 要的群不在清單裡就點下面那行切成手動輸入。

群組 ID 去哪裡拿？ LINE App 裡看不到群組 ID——它不是給使用者看的東西。 唯一的取得處是我們自己的 通訊管道 頁： 找到那個群，點一下群名下面那行灰色小字，就會複製完整的 ID。
為什麼有些帳號看得到清單、有些看不到？ 清單只列出機器人已經收過訊息的群（群組要收到訊息才會被登錄）， 而且需要「檢視 LINE 群組」的權限。兩者缺一就會變成情況 A。 這不影響設定結果——手動貼 ID 跟從清單選，存進去是一樣的東西。
8按「儲存規則」

存好之後畫面會給你一段網址，下一節要用。

3回到 Ragic 貼上網址

整個流程最常出錯就在這一步，慢一點做
1複製剛才那段網址

存檔後畫面上就有。之後也可以在規則列表按「複製網址」重新拿，不用刪掉重建。

2在 Ragic 打開同一張表單

就是剛才填路徑的那一張。貼到別張表單是常見錯誤，而且不會有任何錯誤訊息。

3點上方的「工具」，在展開的選單裡找 Webhook

「工具」在表單上方那排（新增 / 工具 / 重新整理）。點下去會展開一整片選單， 分成六個區塊。Webhook 在右下角那一區「同步與通知」裡面。

⚠️ 不要找「工具 → 同步」這種下一層選單 Ragic 沒有叫「同步」的子選單。「同步與通知」是展開後右下角那一區的標題， Webhook 就直接列在它下面。
找不到的人多半是在找一個不存在的子選單——這是「明明設定了卻沒通知」的頭號原因。
4把網址貼上去，儲存
5登出 Ragic，再重新登入
這步不能跳過 Ragic 會把設定暫存起來，不重新登入的話剛貼的網址不會真的生效。 我們踩過這個坑：設定完全正確，就是沒通知，登出重進之後立刻就通了。

4測試看看通不通

不要用「等真的有人改資料」來驗證，自己動手測一次
1在 Ragic 那張表隨便改一筆資料，按儲存

改一個不影響業務的欄位就好，例如備註加一個字。

2看那個 LINE 群有沒有收到

正常是幾秒內就到。超過半分鐘沒來，直接看下一節。

連續測兩次卻只收到一則？ 這是正常的。30 秒內同一筆資料重複觸發只會發一次，避免有人連按儲存就洗版。 等 30 秒再測即可。

5沒收到通知？照這個順序查

不要憑猜的，先看「通知紀錄」——它會直接告訴你事情卡在哪一段

第一站永遠是：通知設定 → 通知紀錄 分頁。看到什麼，就往下對照。

完全沒有任何紀錄
代表 Ragic 那邊根本沒把消息送出來，事情還沒到我們這裡。
回第 3 節，依序確認：
① 網址有貼進那一張表單嗎（不是別張）
② 有找對地方嗎——Webhook 在「工具」展開後右下角「同步與通知」那一區
③ 貼完有登出 Ragic 再登入嗎
有紀錄，寫著「未訂閱此異動」
消息有進來，但這條規則沒勾這種異動類型。
按規則的「編輯」，把「更新資料」（或你需要的那種）勾起來。
有紀錄，寫著「重複略過」
30 秒內同一筆資料重複觸發，只送第一次。
正常行為，不用處理。等 30 秒再測。
有紀錄，寫著「推送失敗」
我們收到了，但 LINE 那邊拒絕了。
看那一列的「說明」欄。最常見的是機器人已經被移出那個群組，把它重新加回去即可。
有紀錄，寫著「已送出」，但群組還是沒訊息
我們這端完成了推送。
檢查機器人是不是還在那個群裡；也確認你看的是不是同一個群。
收到了，但內容都是「（未填）」
通知有發，但欄位抓不到值。
點開那一列會展開診斷說明，它會直接告訴你是哪一種：
① 那些欄位在 Ragic 本來就是空的 → 正常
② 勾的欄位跟這張表單對不上 → 表單改過了，重新「抓取欄位」再存一次
「抓取欄位」失敗時，畫面會直接告訴你哪裡錯 訊息會明確指出是帳號名、表單路徑、表單索引還是金鑰的問題， 照它說的那一格去改就好。不要看到失敗就先去換金鑰 —— 多數情況不是金鑰的問題。
紀錄裡「規則」那欄寫著「—（舊版記錄 · 未留規則）」 那是舊版系統留下來的資料，當時沒有記錄是哪條規則觸發的。不是規則被刪掉，不用去找。

6之後要修改規則

直接改就好，不要刪掉重建
規則列表上有「編輯」按鈕 要換欄位、改通知對象、加勾一種異動類型，都用編輯。 改完網址不變，不用回 Ragic 重貼。
不要用「刪掉重建」來修改 重建會產生一段新的網址，舊的立刻失效。 你會得到一條看起來正常、實際上收不到任何消息的規則——除非你記得回 Ragic 把新網址再貼一次。
你想做的怎麼做
換掉幾個顯示欄位編輯 → 步驟三重新勾選 → 儲存
改成通知另一個群編輯 → 步驟四換下拉 → 儲存
暫時不要收通知規則列表把它停用（不要刪，之後還要用）
換成另一張 Ragic 表單這個要新增一條規則——網址是綁表單的，換表單等於換一條線
這份手冊對應的是畫面上的實際操作。若畫面與此處描述不符，以畫面為準並回報給開發。
