# 台灣福祉戰情室 — 系統設計文件（開發用）

> 工程建置規格，供直接實作。商業背景/KPI/POC/簡報敘事見 `台灣福祉_..._v0.7_完整版.md`，本文不重複。
> 技術棧假設：TypeScript/Node（服務層）、PostgreSQL（RLS）、Redis（鎖/佇列）、Claude API（雲端 LLM）、Whisper/BGE-M3/PaddleOCR（地端）。部署：**服務與資料層地端**，LLM 吃去識別內容上雲。

## 1. 系統上下文與部署拓撲

```
                LINE Platform ──webhook──▶ [1] Bot/Ingest ──▶ raw_messages(DB)
                                                                    │
  ┌──────────────── 地端 On-prem（Docker Compose / K8s）────────────┼───────────────┐
  │ [1] Bot/Ingest 服務   [2] 去識別前處理   [3] 批次 Worker(cron)                     │
  │ [4] 地端多模態(Whisper/OCR/NER/BGE-M3)   [5] Grounding   [6] 簽核/同步 Worker      │
  │ [7] Web API + 前端(戰情室)   [8] PostgreSQL(RLS)   [9] Redis(鎖/outbox佇列)        │
  │ [10] RAG 索引(BGE-M3 向量庫)                                                       │
  └───────────────────────────┬──────────────────────────────────────────────────┘
                              │ 僅去識別文本 + 已遮罩圖（HTTPS）
                              ▼
                  雲端 Claude API（分類/抽取/vision/摘要）
  外部整合：Ragic HTTP API（讀主檔/寫結果）、工研院 RAG（技術研發群組）
```

**信任邊界**：只有「去識別文本＋遮罩圖」跨越地端→雲端。對照表、原始媒體、語音、RAG 索引不跨界。

## 3. 資料模型（PostgreSQL DDL）

> 完整表清單。所有業務表帶 `tenant_id`，並套 RLS（§4.3）。索引列於各表後。

```sql
-- 3.1 租戶/組織/權限
CREATE TABLE tenants (
  tenant_id uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  tenant_name text NOT NULL, industry text,
  onboard_status text NOT NULL CHECK (onboard_status IN ('洽談中','測試中','正式上線','暫停')),
  created_at timestamptz NOT NULL DEFAULT now());

CREATE TABLE departments (
  department_id uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  tenant_id uuid NOT NULL REFERENCES tenants,
  department_name text NOT NULL,
  line_group_id text NOT NULL,
  extraction_schema text NOT NULL,          -- 綁定抽取 schema key（§7 路由）
  ragic_table text NOT NULL,
  UNIQUE (tenant_id, line_group_id));
CREATE INDEX ON departments (line_group_id);

CREATE TABLE users (
  user_id uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  tenant_id uuid REFERENCES tenants,        -- aiproot_admin/consultant 為 NULL
  employee_id uuid,
  role text NOT NULL CHECK (role IN ('aiproot_admin','consultant','tenant_admin','group_owner')),
  department_id uuid REFERENCES departments, -- group_owner 專屬
  line_user_id text, password_hash text);

CREATE TABLE consultant_assignments (
  assignment_id uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  consultant_user_id uuid NOT NULL REFERENCES users,
  tenant_id uuid NOT NULL REFERENCES tenants,
  status text NOT NULL DEFAULT 'active' CHECK (status IN ('active','ended')),
  can_proxy_signoff boolean NOT NULL DEFAULT false,
  authorized_by uuid, authorized_at timestamptz, assigned_at timestamptz DEFAULT now(),
  UNIQUE (consultant_user_id, tenant_id));

CREATE TABLE licenses (
  license_id uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  tenant_id uuid NOT NULL REFERENCES tenants,
  license_type text CHECK (license_type IN ('試用','正式','停用')),
  seat_limit int NOT NULL,                  -- seat = 可登入 users 帳號數
  billing_cycle text, start_date date, end_date date,
  status text CHECK (status IN ('active','suspended','expired')));

CREATE TABLE subsidy_applications (          -- 僅 aiproot_admin
  application_id uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  tenant_id uuid NOT NULL REFERENCES tenants,
  measure text CHECK (measure IN ('措施1階段一','措施1階段二','措施1階段三','措施2')),
  status text CHECK (status IN ('準備中','已送件','審查中','已核准','已撥款')),
  amount numeric, updated_at timestamptz DEFAULT now());

-- 3.2 原始訊息 / 同意 / 保存
CREATE TABLE raw_messages (
  id uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  tenant_id uuid NOT NULL REFERENCES tenants,
  department_id uuid NOT NULL REFERENCES departments,
  group_id text NOT NULL,
  sender_pseudo text NOT NULL,              -- 假名化 user
  message_type text CHECK (message_type IN ('text','image','video','file')),
  content text, media_object_key text,      -- 地端物件儲存 key（非 URL）
  reply_to_message_id text,
  created_at timestamptz NOT NULL,
  processed boolean NOT NULL DEFAULT false,
  batch_run_id uuid,                        -- 冪等：本則由哪次批次處理
  opt_out boolean NOT NULL DEFAULT false);
CREATE INDEX ON raw_messages (tenant_id, department_id, processed, created_at);

CREATE TABLE consent_log (
  tenant_id uuid REFERENCES tenants, group_id text,
  notice_date timestamptz, notice_text text, notice_version text,
  opt_out_user_ids text[]);

CREATE TABLE retention_policy (
  tenant_id uuid PRIMARY KEY REFERENCES tenants,
  raw_message_days int NOT NULL DEFAULT 60, media_days int NOT NULL DEFAULT 30);

-- 3.3 主檔（grounding）/ 詞庫 / 假名對照（假名對照僅地端、不含 tenant RLS 對雲端）
CREATE TABLE employees (
  employee_id uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  tenant_id uuid NOT NULL REFERENCES tenants,
  name text, line_user_id text, role text, is_group_owner boolean DEFAULT false);
CREATE TABLE vehicles (
  vehicle_id uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  tenant_id uuid NOT NULL REFERENCES tenants,
  vehicle_no text, vehicle_type text, customer_name text);
CREATE TABLE work_orders (
  wo_id uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  tenant_id uuid NOT NULL REFERENCES tenants, wo_code text, customer_name text, status text);
CREATE TABLE tenant_vocabulary (
  id uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  tenant_id uuid NOT NULL REFERENCES tenants,
  term text, standard_meaning text, category text, usage_count int DEFAULT 0,
  source text DEFAULT 'manual' CHECK (source IN ('manual','correction')),
  updated_at timestamptz DEFAULT now());
CREATE TABLE employee_pseudonym_map (       -- 敏感：對照表；限地端服務帳號可讀
  tenant_id uuid NOT NULL REFERENCES tenants,
  entity_type text CHECK (entity_type IN ('employee','vehicle','customer')),
  entity_id uuid NOT NULL, pseudo_token text NOT NULL,
  PRIMARY KEY (tenant_id, pseudo_token));

-- 3.4 tickets / 知識卡片 / 簽核 / 同步
CREATE TABLE tickets (
  ticket_id uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  tenant_id uuid NOT NULL REFERENCES tenants,
  department_id uuid NOT NULL REFERENCES departments,   -- 路由主鍵（取代 module_type）
  category text, summary text, status text,
  linked_employee_id uuid, linked_vehicle_id uuid, linked_wo_id uuid,
  confidence text CHECK (confidence IN ('high','medium','low')),
  confirm_status text NOT NULL DEFAULT '待簽核' CHECK (confirm_status IN ('待簽核','已簽核','逾時警示')),
  confirmed_by uuid, confirmed_at timestamptz, proxy_by uuid,
  sync_status_ragic text NOT NULL DEFAULT '未同步' CHECK (sync_status_ragic IN ('未同步','同步中','已同步','同步失敗')),
  sync_status_itri  text NOT NULL DEFAULT '未同步',
  source_message_ids uuid[], message_count int,
  created_at timestamptz DEFAULT now(), updated_at timestamptz DEFAULT now());
CREATE INDEX ON tickets (tenant_id, department_id, confirm_status, created_at);
CREATE INDEX ON tickets (tenant_id, confidence, created_at);

CREATE TABLE knowledge_cards (
  card_id uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  tenant_id uuid NOT NULL REFERENCES tenants, department_id uuid REFERENCES departments,
  ticket_id uuid REFERENCES tickets,
  title text, body text, entity_tags text[], source_message_ids uuid[],
  indexed_to_rag boolean DEFAULT false, created_at timestamptz DEFAULT now());

CREATE TABLE pending_review (
  ticket_id uuid PRIMARY KEY REFERENCES tickets,
  reason text, reviewed_by uuid, reviewed_at timestamptz);
CREATE TABLE correction_log (
  id uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  tenant_id uuid NOT NULL REFERENCES tenants, ticket_id uuid REFERENCES tickets,

CREATE TABLE ragic_sync_outbox (
  id bigserial PRIMARY KEY, ticket_id uuid NOT NULL REFERENCES tickets,
  target text CHECK (target IN ('ragic','itri')), payload jsonb,
  attempts int DEFAULT 0, last_error text, created_at timestamptz DEFAULT now(), done_at timestamptz);
CREATE INDEX ON ragic_sync_outbox (done_at) WHERE done_at IS NULL;

-- 3.5 稽核
CREATE TABLE audit_log (
  id bigserial PRIMARY KEY, actor_user_id uuid, actor_role text,
  action text, tenant_id uuid, target_id uuid,
  result text CHECK (result IN ('allowed','denied')), ip inet, created_at timestamptz DEFAULT now());
CREATE INDEX ON audit_log (tenant_id, created_at);
```

## 4. 角色權限與強制點（三層防禦）

### 4.1 RBAC 矩陣
| 資源/操作 | aiproot_admin | consultant(指派內) | tenant_admin | group_owner |
|---|---|---|---|---|
| 客戶清單（聚合） | ✅全部 | ✅指派 | ✖ | ✖ |
| 補助漏斗 | ✅ | ✖ | ✖ | ✖ |
| tickets.summary 內容 | ✖(僅 COUNT) | ✅ | ✅ | ✅本群組 |
| 簽核面板檢視 | ✖ | ✅ | ✅全部門 | ✅本群組 |
| 執行簽核 | ✖ | 代簽(授權+標記) | 預設不越權 | ✅ |
| 跨租戶 | 聚合 | ✖非指派 | ✖ | ✖ |

### 4.2 API 中介層
JWT payload `{ user_id, role, tenant_id, department_id }`；每請求解析 role → 設定 DB session 變數 `SET app.current_tenant / app.current_role / app.current_department`，供 RLS 使用；並寫 `audit_log`。

### 4.3 DB RLS（第二道防線，範例）
```sql
ALTER TABLE tickets ENABLE ROW LEVEL SECURITY;
-- tenant_admin/group_owner：僅本租戶（group_owner 再限 department）
CREATE POLICY t_tenant ON tickets USING (
  current_setting('app.current_role') IN ('tenant_admin','consultant')
    AND tenant_id = current_setting('app.current_tenant')::uuid
  OR current_setting('app.current_role') = 'group_owner'
    AND tenant_id = current_setting('app.current_tenant')::uuid
    AND department_id = current_setting('app.current_department')::uuid);
-- aiproot_admin：不給 row 存取；改走聚合 VIEW（物理隔離 summary）
CREATE VIEW v_tenant_health AS
  SELECT tenant_id, department_id, count(*) FILTER (WHERE confirm_status='已簽核') AS signed,
         count(*) AS total, count(*) FILTER (WHERE confidence='high') AS high
  FROM tickets GROUP BY tenant_id, department_id;   -- 不含 summary 欄
-- consultant 需先通過 consultant_assignments 檢查（於 API 層 + 可加 policy）
```

## 5. 訊息接入與每日批次（流程時序）

### 5.1 Ingest（即時）
```
LINE webhook → 驗簽章(X-Line-Signature) → 依 group_id 找 department → 寫 raw_messages(processed=false)
  → 若 media：立即下載 content → 存物件儲存 → 記 media_object_key（LINE URL 有時效）
  → opt_out 成員訊息標 opt_out=true（不分析）
```

### 5.2 批次（cron，冪等）
```
03:00 Asia/Taipei，每租戶一次：
1. 取 Redis 鎖 lock:batch:{tenant_id}（防重入）；產 batch_run_id
2. SELECT raw_messages WHERE tenant_id=? AND processed=false AND opt_out=false ORDER BY created_at
3. 去識別前處理（§6）→ 依 department 分組
4. 每 department：會話切分＋事件聚類 → 呼叫該 department 的抽取 schema（§7）
5. LLM 回傳 → grounding 還原 token（§7.5）→ upsert tickets（source_message_ids 冪等去重）
6. 抽 KM → knowledge_cards → 佇列 RAG 索引
7. UPDATE raw_messages SET processed=true, batch_run_id=? WHERE id IN (...)
8. 逾時掃描：confirm_status='待簽核' AND now()-created_at > overdue_window → '逾時警示'
9. 釋放鎖；失敗自動重試 3 次後告警（不標 processed，下次重跑）
```
**冪等鍵**：`(tenant_id, source_message_ids)` 去重，重跑不重複產 ticket。

## 6. 去識別前處理（地端）

- **偵測**：規則（車號正則、電話）＋ 輕量繁中 NER（人名/客戶/地址）。
- **替換**：實體 → `EMP_/VEH_/CUST_` token；查/寫 `employee_pseudonym_map`（同實體同 token）。
- **輸出**：去識別文本；圖像先過人臉/車牌遮罩。**對照表不出地端**。
- 還原（§7.5）：LLM 結果中的 token 依對照表回填為 `*_id`。

## 7. AI 分析管線

### 7.1 路由
`raw_messages.group_id → departments.line_group_id → departments.extraction_schema`。schema key 對應一組 prompt＋輸出 JSON schema（zod 驗證）。

### 7.2 抽取（雲端 Claude，分階）
每 department 綁定模型與 schema（見 §3.2 選型表）。呼叫用 structured output（`output_config.format`）＋ prompt caching（system+主檔詞庫為穩定前綴）。每筆輸出含 `confidence`；`low` 標 `needs_review`。

### 7.3 事件聚類/合併
同 department 內，以時間鄰近＋實體重疊（同車號/工單）＋語意相似聚類；一事件多訊息 → 單 ticket，狀態 open→in_progress→resolved 隨後續訊息更新；`source_message_ids` 累積。

### 7.4 KM 抽取
偵測「經驗/根因/預防建議」語意 → 生成 `knowledge_cards`（title/body/entity_tags/source）→ BGE-M3 索引。

### 7.5 Grounding
token → 主檔比對（employees/vehicles/work_orders）＋ `tenant_vocabulary` 詞庫消歧；對不到 → 保留原文並降 confidence、進 `pending_review`。

### 7.6 信心度
誠實輸出，不系統性高估（system prompt 強制）；戰情室高信心比例即由此統計。

## 8. 簽核與同步

### 8.1 簽核狀態機
```
待簽核 ──group_owner 確認──▶ 已簽核 ──enqueue outbox──▶ (sync worker)
   └──now-created_at>overdue_window──▶ 逾時警示 ──補簽──▶ 已簽核
低信心(needs_review) 須先補資訊才可確認（API 擋）
代簽：consultant 且 can_proxy_signoff=true → 已簽核, proxy_by=consultant, audit_log(proxy_sign)
```

### 8.2 同步（Outbox）
```
確認交易內：UPDATE tickets SET confirm_status='已簽核',confirmed_by,confirmed_at
            + INSERT ragic_sync_outbox(target='ragic',payload)  （同交易，保證入列）
sync worker：SELECT ... WHERE done_at IS NULL FOR UPDATE SKIP LOCKED
            → Ragic API 寫入 → 成功:sync_status_ragic='已同步',done_at=now()
            → 失敗:attempts++,last_error, 指數退避重試；ticket 顯示「同步失敗」徽章（不回退簽核）
技術研發群組另 enqueue target='itri'（工研院 RAG）
```

## 9. 指標計算與健康度（戰情室資料源）

參考實作：`src/warroom/aggregate.ts`（已實跑）。

| 指標 | 公式 | 來源 |
|---|---|---|
| 簽核完成率 | 已簽核 department ÷ 6 | tickets.confirm_status |
| 健康度 | 綠燈 department ÷ 6 | 狀態機↓ |
| 高信心比例 | high ÷ 當日已標 | tickets.confidence |
| 待人工確認 | count(pending_review WHERE reviewed_at IS NULL) | pending_review |

**健康度狀態機（參數可租戶設定）**：`active_window=24h, overdue_window=24h, inactive_red=72h`
```
綠：活動≤active_window 且 無逾時 且 無低信心待簽核
黃：活動≤active_window 且（低信心待補 或 待簽核未逾時）
紅：待簽核逾 overdue_window  或  無活動>inactive_red
```

## 10. API 介面契約

### 10.1 內部（戰情室）
| Method Path | 角色 | 回傳 |
|---|---|---|
| POST `/auth/login` | 全 | JWT |
| GET `/tenants` | aiproot/consultant | 客戶清單（聚合；consultant 限指派） |
| GET `/subsidy/funnel` | aiproot | measure×status 計數 |
| GET `/warroom?tenant_id` | tenant_admin/consultant/group_owner | 三指標＋六群組＋metrics（依 role 過濾） |
| GET `/signoff?department_id` | group_owner/tenant_admin | 當日待簽核 tickets（含 confidence） |
| POST `/signoff` `{ticket_ids[]}` | group_owner(自群組)/代簽 | 確認→入 outbox |
| GET `/tickets/:id` | 內容角色 | ticket 明細（RLS gated） |
| POST `/km/query` `{q}` | 內容角色 | RAG 檢索答案＋來源 |

### 10.2 外部
- **Ragic**：`GET` 主檔（employees/vehicles/work_orders/詞庫）；`POST` 各群組目標表（附冪等鍵）。失敗語義配合 Outbox。
- **工研院 RAG**：技術研發群組知識同步（契約待定，見完整版 §二十）。
- **LINE**：webhook 接收；`reply`（Flex Message，不計費）用於簽核卡片與反向問答。

## 12. 可觀測性與失效

- **audit_log**：所有 view/sign/proxy/export/km_query。
- **告警**：批次失敗、Outbox 積壓、LLM 連續失敗、逾時警示數異常。
- **LLM 失效**：佇列等待或切地端小模型，戰情室標「分析延遲」，不靜默跳過。
- **日誌**：結構化，含 tenant_id/batch_run_id 便於追蹤。

## 13. 測試規格（開發驗收）

| 類型 | 案例 |
|---|---|
| 單元 | 去識別遮罩正確率；事件聚類合併；grounding 消歧；健康度狀態機邊界 |
| 整合 | 批次冪等（重跑不重複產 ticket）；Outbox 重試；Ragic 寫入失敗不回退簽核 |
| 權限（E2E） | tenant(A) 查 tenant(B)→403/空（API＋RLS 雙驗）；aiproot 查 tickets→僅 COUNT，取不到 summary |
| 反幻覺 | 模糊訊息（無車號「門壞了」）→ low+needs_review+攔截；未簽核不入 Ragic |
| 簽核 gate | 未簽核不進 Ragic；簽核後 audit_log 有記錄；逾時自動轉警示 |
| 代簽 | 授權後代簽→proxy_by＋徽章＋audit(proxy_sign) |
| 不外流 | 抽查上雲 payload → 皆 token、無原始媒體/語音 |
