> 每個非 trivial 模組走 M0（design doc ＋ OQ 裁定）→ M1–M4 落地 → M5 FMEA（R17）→ 標 ✅。
> 設計文件在 `docs/modules/<module>.md`。

## 怎麼讀這份索引

**狀態以「prod 有沒有資料在跑」為準，不以 doc 開頭寫什麼為準。**

2026-07-30 重整時發現索引與現實有明顯漂移 —— `employee-line-binding`、`warroom-task-board`、
`personal-daily-report` 都標「APPROVED · 進 M1」，`task-completion-tracking` 標「M0 DRAFT 待裁定」，
`media-and-vision` 標「待 push」，但這五個**都已經在 prod 跑了好幾天**
（分別有 9 / 51 / 31 / 18 / 207 筆資料）。

doc 的開頭是「寫的時候」的狀態，落地之後常常沒人回來改。
所以「已上線」那一節每一列都附**上線證據**（prod 的實際筆數），
下次重整時可以直接驗，不必再靠讀 doc 猜。

| 分節 | 意思 |
|---|---|
| ✅ **已上線** | prod 有資料在跑 · 可以拿去跟客戶講的 |
| 🔨 **部分上線** | 有東西在跑，但還有里程碑沒做（每列註明還缺什麼）|
| 📋 **待裁定 / 未實作** | M0 doc 寫完了，等 OQ 裁定或前置條件才動工 |
| 🧊 **已凍結** | 刻意不做 · 每列附解凍條件 |
| 📚 **參考文件** | 設計研究、歷史決策脈絡 · 非落地模組 |
