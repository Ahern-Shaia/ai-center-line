# LIFF「我的日報」前端設計研究（A5：先研究、再設計 · 站在巨人的肩膀）

> 狀態：📝 **M0 設計研究草案**（2026-08-01）· 待用戶選方向後才進 M1
> 觸發：用戶回饋「LINE LIFF 前端排版需再設計」，並指定**先寫 design doc → 再做 UI mockup**。
> 實測問題（截圖）：編輯項目時「時間」輸入框在 LINE in-app webview **爆高占滿半屏**；整體是把桌機兩欄式表單塞進手機。
>
> 適用 profile：`observability-light`（CLAUDE.md R16）· **但這是 mobile-first LIFF**（在 LINE 內建瀏覽器開），需以手機為第一目標套 token，不是把桌機縮小。
> 現況元件：`web/src/personal-report/MyDailyReport.tsx`（同一元件桌機/LIFF 共用）· CSS `.pdr-*`。

---

## 0. 問題定性（不是「醜」，是「桌機表單硬塞進手機」）

`MyDailyReport.tsx` 桌機/LIFF 共用同一份 markup，`.pdr-*` 樣式以桌機為主、手機靠零星 media query 補。實測痛點：

1. **編輯模式輸入框爆高**：`.pdr-time`（`<input>`）在 LINE webview 被撐到半屏高（截圖 192282）——桌機 `flex:0 0 200px`、手機 `flex:1 1 100%`，但在 webview 的 flex-column 下高度失控。
2. **桌機味的密度**：兩欄 row、小字 label、desktop hover 態，在手機上點擊區太小、掃視吃力。
3. **狀態多但沒為手機分層**：loading / 空(有訊息) / 空(無訊息) / 失敗 / 有項目 / 編輯 / 已送出 / 指派任務建議 —— 8 種態擠在一頁，手機上層次不清。
4. **送出動線**：送出鈕在很下面，長列表要滑到底；手機該用**固定底欄**。

**核心：LIFF 是員工每天下班在手機上花 30 秒的東西 —— 要「大拇指友善、少判斷、掃一眼就改、一鍵送出」。**

---

## 1. 參考對象（§A5 · ≥3 真實產品 · 手機 quick-review-and-submit）

### 1. Todoist / Google Tasks（手機 quick edit · 標竿：點一行就地編輯）
- list 是**單欄卡片**，點一項**就地展開**成輸入，不跳頁、不彈大框。
- 欄位**逐一聚焦**、鍵盤彈起時內容自動上推（keyboard-aware），輸入框高度固定不亂長。
- 偷：**單欄 + tap-to-edit inline + 固定高度欄位 + 大點擊區**。

### 2. Linear mobile（標竿：極簡 chrome + 底部動作）
- 卡片乾淨、次要資訊收起；主要動作放**底部固定條**，滑到哪都按得到。
- 偷：**minimal chrome + 底部 sticky 動作條**。

### 3. Apple 提醒事項 / Notes checklist（標竿：清單就地改，不用表單）
- 每一列＝一個可點的文字行，點了游標就進去改，**沒有「時間/標題/內容」三個分離大框**。
- 偷：**把「一項日報」當成一張可點改的卡，而非一張多欄表單**。

### 4. Material 3 / iOS HIG 表單欄位（標竿：正確的欄位高度與 label）
- text field 有明確高度、label 在框上、觸控目標 ≥44px；`font-size ≥16px` 避免 iOS 自動放大。
- 偷：**明確 sizing（防爆高）+ 16px 字 + 44px 觸控**。

> **共通洞察**：手機上「改一份 AI 草稿再送出」＝**單欄卡片清單 + 就地 inline 編輯（欄位固定高）+ 底部固定送出條**，不是桌機多欄表單縮小。

## 2. 向上設計（mobile-first + observability-light token）

### 2.1 版面骨架
- **單欄**、內容 max-width 撐滿手機、`.pane` padding 縮（已有 <400px 規則，擴到主要斷點）。
- **頂部精簡 header**：標題「我的日報 · 8/1 週六」+ 日期切換（下拉）+「重新生成」收成 icon/次要鈕。
- **底部固定送出條**（sticky footer）：「N 項待送出　[儲存草稿][送出日報]」，長列表也一直在。

### 2.2 一項日報＝一張可點改的卡（取代多欄表單）
- 未編輯：卡片顯示 `序號 · 標題`、下方 `時間 · 摘要`、（有）`追蹤`。整卡可點→進編輯。
- 編輯：**就地展開**，欄位單欄堆疊、**每個欄位固定高度**（時間 44px 單行、標題 44px、內容 auto-grow textarea 起始 3 行、追蹤 44px），**明確 `min-height` + `max-height` 防 webview 爆高**。完成鈕就近。
- 時間欄：手機給**大按鈕式輸入**或 `inputmode` 數字鍵盤，維持既有「830→08:30」自動補冒號。

### 2.3 空/引導態分層（手機掃一眼就懂下一步）
- 空 + 有 pending 訊息：大字「你今日已私訊 **3** 則」+ **主 CTA「立即整理」**（大鈕）+ 原始訊息小卡列。
- 空 + 無訊息：一句「私訊 bot 幾則今日工作，{aiRunAt} 會自動整理」+ 次級說明。
- 失敗：紅卡 + 重試。
- 指派任務/打卡建議：**只在今天**（已修 isToday）顯示，做成「+ 一鍵加入」的小卡，不佔主視覺。

### 2.4 observability-light token（不發明）
- canvas/surface/well/hairline/墨/primary 靛藍/語意色沿用；圓角 6-8px；數字 tabular。
- 觸控：所有可點 ≥44px；欄位字 16px（避免 iOS zoom）；`.st-dot`+`.nc-pill` 表狀態。

### 2.5 §A6 所有狀態
| 狀態 | 手機呈現 |
|---|---|
| loading | skeleton 卡 |
| AI 草稿 | 卡片清單 + 底部送出條 |
| 空(有訊息) | 「已私訊 N 則 · 立即整理」大 CTA + 原始訊息 |
| 空(無訊息) | 一句引導 + aiRunAt |
| 失敗 | 紅卡 + 重試 |
| 編輯中 | 就地展開、欄位固定高、完成鈕就近 |
| 已送出 | 唯讀卡 + 「已送出」狀態；有新訊息時提示可再送 |

## 3. 版面方向（請用戶選一個 · mockup 會各出一版）

- **方向 A：清單卡 + 底部送出條（對標 Todoist/Linear）** — 單欄卡片、tap-to-edit inline、sticky 底部送出。推薦。
- **方向 B：分段流程（草稿→確認→送出 三步）** — 像結帳流程分步，逐步引導，適合很不熟手機的員工，但多點幾下。
- **方向 C：現況最小修** — 只修爆高欄位 + 觸控尺寸 + 底部鈕，不改結構（最快、但仍是桌機味）。
