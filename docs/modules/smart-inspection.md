## 1. 目標與範圍

### 1.1 目標

1. 鮮湧機聯網戰情室多一塊**巡檢**，展示「16 台相機在看廠內儀表」這件事實際跑起來是什麼樣子。
2. 頁面上出現的每一個巡檢數字，都是**從真實 CSV 算出來的**，不是 `Math.random()` 的示意值 ——
   這是這批死資料唯一、也是最大的價值：**它讓 demo 變得可查證**。
3. 不可誤導：資料區間要標明，判讀不可信的相機要說不可信。

### 1.2 這份 doc 的核心主張

> **現行 CSV 的「狀態」欄不能直接畫上畫面。**
> 24,441 筆裡 24,259 筆（**99.3%**）標成「[異常]」。
> 照它畫，16 台相機會全部紅燈 —— 那張圖就沒有資訊量了。

### 1.3 不做的事

| 不做 | 為什麼 |
|---|---|
| ⛔ **接進 ai-center-line 戰情室 / 任務看板 / tickets** | **兩個是分開的產品**（見檔頭②）。而且一天 12,319 件會洗掉看板，主管會連帶不信任本來準的 AI 任務卡 |
| ⛔ **ingest 端點 / 落庫 / 排程** | **死資料**，不會更新（檔頭①）。做了也沒有第二批 |
| ⛔ **事件 → 任務生命週期** | 同上兩條。這批資料永遠不會產生任務 |
| 幫客戶「修正」讀數（去噪後當真值顯示）| 我們不知道量程，修出來的值沒有工程依據。**不可信就說不可信**，不要硬給數字（R11 禁臆測）|
| 動 LINE / 對話分析那條線 | 完全無關的資料源，而且屬於另一個產品 |
| 讓畫面看起來像即時 | 死資料。**必須標資料區間**（FMEA F-7）|

> **現行系統對每一個數值抖動都叫，唯獨對「相機掛了」不叫。**

### 2.4 ⚠️ 我自己的判準也有同一個陷阱

上表 `.106` / `.144` 我的啟發式判成 🟢，因為我用「**該台自己的中位間隔**」當基準——
一小時才回報一次的相機，它的中位數就是 3600s，於是「準時」。

> **拿自己的歷史當基準，會讓長期壞掉的東西看起來正常。**
> （同類：memory `pitfall_green_because_empty`）

**正解是拿「該型號的設計取樣率」當基準，而那個值只有客戶知道** → OQ-SI-3。

⚠️ 而 `.144` 還疊了第二層問題（解析失敗），見 §2.5 —— **兩個原因疊在一起，畫面上只會看到一個結果**。

### 2.5 ⭐⭐ 我第一版把 `.144` 誤判成「停止回報」—— 其實是解析失敗

初稿寫「`.144` 08-25、08-26 完全沒有資料」。**錯的。**

那兩天的資料一直都在，只是這台的時間格式跟別台不一樣：

| | 格式 | 例 |
|---|---|---|
| 其餘 15 台 | `%Y-%m-%d %H:%M:%S` | `2026-08-25 14:42:10` |
| **`.144`** | `%Y/%m/%d %H:%M` | `2026/8/25 16:42`（斜線、月日不補零、**沒有秒**）|

我的第一版解析器只認前者，`strptime` 失敗就 `continue` —— **31 列被靜默丟掉**，
於是這台看起來像 08-27 才突然開始回報。

> **「沒有資料」和「我讀不到資料」在畫面上長得一模一樣，但處置完全相反。**
> 一個是叫人去現場修相機，一個是叫人來修我們的 parser。
>
> 修法：`scripts/inspection-probe.py` 現在**解析失敗一律計數並印出來**，不可以 `continue` 就算了。
> 同類：memory `pitfall_green_because_empty`。

⚠️ 這也代表現場**至少有兩種寫檔器**。做 ingest（OQ-SI-1 選 B）時，
格式白名單要涵蓋全部，而且**不在白名單內要報錯不要跳過**。

## 4. 提議的呈現方式

### 4.0 ⭐ 兩種形狀，取捨因「死資料 + demo」而翻轉

我原本建議「掛在平面圖上、不開新分頁」，理由是「相機就是在看那些機台，
拆兩張圖等於要人自己對位置」。**那個理由成立的前提是我們知道哪台看哪台。**
我們不知道（§5），而且那張表只有客戶給得出來。

| | **形狀 A · 平面圖圖層** | **形狀 B · 獨立「巡檢」分頁** |
|---|---|---|
| 說服力 | 高 —— 看得到相機正對著哪台機台 | 中 —— 只看得到「16 台相機在跑」 |
| 前置 | ⛔ 要 16 列對應表（客戶）| ✅ 無 · 現在就能做 |
| 錯位風險 | 標錯機台比沒有更糟（F-6）| 無 —— 不宣稱任何位置 |
| 工作量 | A2 + 座標調校 | A2（少了座標）|

⭐ **建議：先做 B，對應表到了再升級成 A。**
B 的相機卡片與讀數曲線面板（A3）**在 A 裡完全複用**，不是白工 ——
升級要加的只有「把卡片釘到平面圖座標上」這一步。

→ 新增 **OQ-SI-9** 請你裁定。以下 §4.1–4.5 是**形狀 A** 的規格；
選 B 的話 §4.2（三色語意）、§4.3（點擊面板）、§4.5（不要放的東西）**原樣適用**，
只有 §4.1（圖層座標）換成卡片格。

### 4.2 ⭐⭐ 三色語意必須換掉（本 doc 最重要的一條）

`dev` 的 g/y/r 是「溫度偏離目標」。相機**不能照抄**：

| 燈 | 判準 | 主管該做什麼 | 現況台數 |
|:-:|---|---|--:|
| 🟢 | 正常回報、讀數在量程內 | 不用做事 | **3** |
| 🟡 | **讀數不可信**（判讀跳動 / 超出量程）| 找人重新框 ROI / 調焦 | **8** |
| 🔴 | **停止回報** | 找人去看相機或網路 | **5** |
| ⚪ | 未納入本期 | — | 0 |

| 192.168.134.101 | camera_01 | 2F? | ST-2F-01? | ? | ? | ? |

## 7. ⛔ 為什麼這批資料**永遠**不會進任務看板

檔頭②已經定調兩個產品分開。但即使假設它們是同一個產品，數字也不允許：

| 判準 | 件數 | 換算/天 |
|---|--:|--:|
| 現行 CSV 的「[異常]」欄 | 24,259 | **12,319** |
| ① 停止回報（> 中位間隔 20 倍且 > 10 分）| 680 | 345 |
| ② 讀數離譜（> 該台 P95 的 3 倍）| 304 | 154 |
| ③ 去抖動（連續 3 筆偏離中位數 6×MAD）| 151 | 77 |
| **①+②+③** | **1,135** | **576** |

換三種判準比現行好 21 倍，**離「主管一天核對得完」（約 20 件）還差 29 倍**。

> 這段留著不是為了規劃，是為了**擋掉未來某次「不然把巡檢也丟進任務看板吧」的提議**。
> 答案是不行，而且不行的理由有兩層：產品邊界（檔頭②）＋ 量級（這張表）。

⚠️ 順帶：①②③ 是**統計猜測不是工程判準**。沒有量程（OQ-SI-2）之前，
「離譜」只能靠該台自己的分佈推 —— 而那正是 §2.4 的陷阱。
